LIBER NOCTIS: GIT COMMANDS
==========================

Day-to-day work happens on the "dev" branch. "main" is what gets published
(once the repo is public and Pages is on), so only merge into main when dev is good.


-----------------------------------------------------------------
1. SETTING UP A NEW DEVICE (once per computer)
-----------------------------------------------------------------

Install git and the GitHub CLI tool ("gh"):

    CachyOS / Arch:   sudo pacman -S git github-cli
    Windows:          winget install Git.Git GitHub.cli
    macOS:            brew install git gh

Log in to GitHub through gh. This replaces passwords: GitHub doesn't
accept your account password for git any more.

    gh auth login

    Answer:  GitHub.com  ->  HTTPS  ->  "Authenticate Git with your
             GitHub credentials?" Yes  ->  Login with a web browser
    Then paste the one-time code it shows into the page it opens.

Tell git who you are (once per device):

    git config --global user.name "Tay"
    git config --global user.email "tatelaird@gmail.com"

Download the project and switch to the dev branch:

    gh repo clone Tayvall/Liber-Noctis
    cd Liber-Noctis
    git switch dev

Check it works:

    python DevTools/serve.py        (opens the book; run again to stop)


-----------------------------------------------------------------
2. EVERY TIME YOU SIT DOWN TO WORK
-----------------------------------------------------------------

Get the latest changes from the other computer FIRST:

    git switch dev
    git pull

Then edit files as normal.


-----------------------------------------------------------------
3. SAVING AND PUSHING YOUR WORK TO DEV
-----------------------------------------------------------------

Check the data and look at it (optional but recommended):

    python .github/scripts/check.py
    python DevTools/serve.py        (run again to stop the preview)

See what you've changed:

    git status
    git diff

Save it (a "commit") and send it to GitHub:

    git add .
    git commit -m "Short note of what you changed"
    git push

Always push before you switch to the other computer.


-----------------------------------------------------------------
4. PUBLISHING: MERGING DEV INTO MAIN (only when dev is good)
-----------------------------------------------------------------

    git switch main
    git pull
    git merge --no-ff --no-commit dev
    git rm -r -q --ignore-unmatch DevTools     (DevTools stays dev-only)
    git commit -m "Publish"
    git push
    git switch dev               (go back to dev to keep working)

The "git rm" line also settles any conflict git reports about DevTools,
so run it even if the merge stops with "CONFLICT (modify/delete)".

The GitHub Action checks everything again. A broken build is never published.


-----------------------------------------------------------------
5. REMOVING, MOVING AND RENAMING FILES
-----------------------------------------------------------------

Delete a file from the repo AND from your computer:

    git rm "path/to/file.json"

Delete a whole folder:

    git rm -r "path/to/folder"

Remove a file from the repo but KEEP it on your computer
(e.g. a personal copy you don't want on GitHub):

    git rm --cached "path/to/file.json"
    (then add its name to .gitignore so it isn't added back by "git add .")

Move or rename a file (git keeps its history):

    git mv "old/name.json" "new/name.json"

Already deleted or moved files in your file manager? That's fine:
"git add ." notices deleted and moved files too. Check with
"git status" (deleted files show as "deleted:") before committing.

After any of the above, save and push as usual:

    git commit -m "Remove/move ..."
    git push

Removed the wrong file by mistake (before committing)?

    git restore --staged "path/to/file.json"
    git restore "path/to/file.json"

Tip: data files are named after their id, so if you rename one in
data/, also change the "id" inside it and any [[links]] or
references to it. "python .github/scripts/check.py" will list any you missed.


-----------------------------------------------------------------
6. WHEN THINGS GO SIDEWAYS
-----------------------------------------------------------------

"Your local changes would be overwritten" when pulling:
  set your changes aside, pull, then bring them back:

    git stash
    git pull
    git stash pop

"rejected ... fetch first" when pushing:
  the other computer pushed something you don't have yet:

    git pull
    git push

A merge conflict (git names the files):
  open each file, keep the right version between the <<<<<<< and >>>>>>>
  markers, delete the marker lines, then:

    git add .
    git commit -m "Merge changes"
    git push

Throw away ALL uncommitted edits (can't be undone):

    git restore .

Which branch am I on?

    git branch                   (the one with * is current)

History of recent commits:

    git log --oneline -10
